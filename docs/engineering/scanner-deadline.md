# 文件扫描总时限与超时状态验证

2026-11-03，负责人 Backend。现有资产上传接口内部修复，OpenAPI 1.51.1 / 143操作和24项迁移保持，无新依赖、接口或存储字段。

原适配器使用 socket.setTimeout，只计算TCP空闲时间。扫描服务持续返回零碎数据会反复推迟超时，最终可能在配置时限后返回clean/infected，或者一直占用上传请求。

现在 CLAMAV_TIMEOUT_MS 是连接、上传、等待完整响应的总时限，默认15000ms；必须是1至2147483647的安全整数，非法配置在连接前503。扫描开始记录单调时钟，设置一次总计时器；连接及数据回调在处理前再复查经过时间，防止事件循环延迟导致计时器尚未运行时接受过期响应。成功、失败及连接关闭均按首次结果结算并清除计时器，扫描之间不共享时限状态。

超时会销毁扫描socket并抛出503，由既有上传应用服务持久化rejected、执行清理，不进入存储put或签名步骤。本人或他人都不能从资产读取接口取得这条非ready资产。现有完整NUL响应、8192字节响应上限、感染422及10MiB图片限制保持。Node定时器不能抢占被阻塞的事件循环，因此这里不承诺严格实时中断；回调恢复后仍会拒绝迟到结果。
