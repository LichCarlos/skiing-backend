## 问题与修复

先前检索 SQL 会排除当前不可见或过期来源，但检索完成后没有继续复核。来源在模型生成前或生成中撤回时，仍可输出旧材料。3 项新增测试先复现失败，日志 `rag-live-evidence-before.log` 保留；修复后专项通过。

新增 Application 端口 `RagEvidenceValidator` 和 PostgreSQL 适配器 `PrismaRagEvidenceValidator`。`RagAnswerService` 对本轮真正进入提示词的来源保留原始分块快照，包括 chunk ID、source key/type/id、完整标题、分块序号及原始正文；快照复制取值，不跟随候选对象后续修改。未知类型、私人收益和因提示词预算被裁掉的来源不会进入快照。最多五个分块，与现有检索上限一致。

复核使用一条参数化 SQL，要求所有分块同时满足：文档仍 indexed、未被人工停用、Embedding model 相同，分块及来源身份/标题/正文仍与快照一致。SQL 复用检索时的 `currentPublicRagSource()`，因此同时检查业务发布/软删除状态、来源 Metadata 的 sourceState、文章分类与公开字段/分组、动态作者、字典祖先可见性等既有规则。未知/私有来源仍拒绝；没有新增商家或管理员私人数据检索入口。不重新执行向量排序，也不接受“只剩一个分块仍有效”作为整轮有效。

检查点为：检索后、首次消费模型流前、每个供应商片段输出前、模型流正常结束后、完整回答保存前和保存后回传 completed 前。无来源时仍返回固定无证据答复，不查询来源校验存储、不调用 Chat。上轮实现的原会话/AI grant/有效 RAG 范围复核继续独立执行。

任一引用过期、删除、被人工停用、业务状态改变或重建替换原分块，整轮结束，避免删掉 citation 后仍输出依赖旧证据的文本。Headers 前通过已有 409 表达引用冲突；headers 后沿用脱敏 `event:error`。未提交完整回答不落 assistant 正文，通过既有 generation token 标记 failed 并取消上游。恢复时由客户端显式使用原 UUID 重试，重新检索当前资料；没有自动重试或新增消息幂等协议。

若来源在数据库保存期间才改变，保存后复核阻止 completed，但不会把已保存回答改写失败。用户可在恢复授权后按原协议核对历史；本次没有修改历史对话保留、引用展示或已完成消息回放策略。

## 验收限制

来源复核、会话授权和保存回答不是同一串行化事务。检查到输出/提交之间仍有竞争窗口，不能宣称来源撤回与生成保存原子互斥。已发送片段无法撤回，已交给外部模型的提示词也不能由本地取消追回；客户端继续将 completed 前片段视为未确认。

检查发生在生成边界，没有即时推送或后台轮询。模型长期无新片段时，在下一片段/结束检查或既有超时取消；尚未实现撤回瞬间停止网络工作。每片段增加一次批量 SQL，包含既有来源可见性表达式，生产负载、查询计划与连接池开销待实测。无证据答复不受来源检查存储故障影响，但会话授权仍正常执行。

源在检索前隐藏已有历史数据库证据；新增生成期四项、真实文章/字段/字典变化全过程、供应商及设备/浏览器仍待验。现有已完成历史消息的来源撤回处理保持既定协议；本次不删除历史、不新增历史引用隐藏规则。项目整体尚未完成。
