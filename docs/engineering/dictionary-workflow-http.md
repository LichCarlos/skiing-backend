# 字典层级管理生产 HTTP 与持久核对

日期：2026-11-03。负责人：Backend。对应 API-M09，沿用 1.51.1 / 143 操作与24项迁移；本阶段后端仅增强验收夹具，不修改生产业务协议。

Web 生产命令及写入门禁通过真实 HTTP 调用 Nest。普通账号由管理员配置角色 grants 后，创建独立字典类型及父子项，更新子项、更新父项、停用子项、修改类型公开标记并停用类型。将父项挂到子项的循环请求由服务端拒绝。管理读取保留停用项，支持分组/状态筛选及后续空页。读取响应返回期间实际替换账号角色，结束身份复核拒绝旧数据；不伪造身份响应。

数据库后置核对独立类型和两项仍存在、父子关联正确、类型 disabled/公开标记 true、父项 active、子项 disabled 及字段值。核对八条成功审计均属于获授权普通账号，动作和目标完整；十条 dictionary.changed.v1 仍 pending，父项四条、子项六条，载荷类型/编号一致。原字典、其他业务及此前验收断言继续保留。事件持久化不等于 Kafka 投递或 RAG 重建成功。

最终运行和日志哈希见[本仓证据](../validation/dictionary-workflow-20261103.json)，前端实现和测试范围见[字典页面说明](../../../web/docs/engineering/dictionary-command-lifecycle.md)。使用原生隔离 PostgreSQL，结束后停止临时 API 和数据库并验证端口、PID及临时密码文件清理；没有启动或重启 Docker。

本轮不代替全库数据库测试，也不证明浏览器 UI、设备、供应商、生产存储、容器和远程 CI 验收。字典命令沿用既有授权及事务保护，未增加客户端版本或跨进程幂等键。D-49/D-50/D-09 保持待决，项目整体未完成。
