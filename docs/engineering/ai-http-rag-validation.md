## 实现修复

会话列表在应用层与 Prisma 仓储入口共同校验分页：`page` 为正安全整数，`pageSize` 为 1–100 的整数，`(page-1)*pageSize` 必须为安全整数且不超过 PostgreSQL int4 上限 2147483647。HTTP 将分页领域错误转换为 400，在访问数据库前拒绝超大偏移，避免无效请求触发 Prisma 错误。排序、默认值和响应结构不变。

消息领域校验接受未知运行时输入，显式拒绝非字符串，再执行 trim、非空与最多 4000 Unicode code point 校验。HTTP DTO 与领域规则仍各自负责入口和内部调用约束。

## 真实联合测试

`test/ai-conversations-http.db-spec.ts` 的 22 项测试使用专用 PostgreSQL 17 / pgvector 数据库和真实 Nest HTTP 服务（随机本地端口，测试结束关闭）。仅替换 Chat、Embedding 两个外部供应商端口，保留以下实际实现：

- 账号、bcrypt 密码、登录、access token、session、Guard 和权限查询。
- Controller、DTO、统一错误、SSE 编码、断流取消和应用服务。
- RAG 文档分块与索引、1024 维 pgvector 检索、来源实时公开状态和快照过滤。
- 会话所有权、消息唯一约束、用户 advisory lock、会话行锁、生成租约、完成及失败持久化。

索引数据使用唯一测试 Embedding 模型标识与固定非零向量，避免与其他测试数据混入同一检索空间。创建公开、草稿、内容已变更的旧索引和私有来源，断言模型输入与最终 citations 仅包含当前公开来源；公开源进入复审后，实际检索无证据并返回固定拒答，Chat 不调用。

| 范围           | 验证结果                                                                                   |
| -------------- | ------------------------------------------------------------------------------------------ |
| 认证与权限     | 游客 401；无 grant 账号全部五种路由 403；撤销角色后旧 access token 请求 403                |
| 所有权与删除   | 列表只含本人；他人、未知会话详情/删除/发送均 404；软删除保留消息、重复本人删除 204         |
| 输入边界       | 非法 UUID、伪造 owner、空白/非字符串/超过 4000 code point、越界分页均 400                  |
| SSE 与保存     | delta 正序输出；completed 对应数据库完整消息和来源；历史及计数不展示生成中/失败占位        |
| 幂等           | 完成重放只有 completed，不调用 Chat/Embedding；同 key 不同内容或仍生成中均 409，无重复消息 |
| 失败恢复       | Embedding 异常、Chat 首片前/后异常和空输出均清理为 failed；同 key 重试复用原两条消息       |
| 错误脱敏       | 首片前统一 JSON 错误；首片后 delta/error，包含 traceId，不包含内部 URL 或供应商错误正文    |
| 取消与删除竞争 | 客户端中断取消外部流，未完成回复不落库且可重试；生成中删除后不允许 completed 保存          |
| 向量约束       | 错维和非有限值向量在调用 Chat 前拒绝；同一逻辑消息可重试                                   |
| 问题上下文     | 同会话已完成轮次的用户问题进入检索与模型输入；其他会话问题和历史 AI 回答不进入             |
| 频控           | 同用户跨六会话并发仅五条成功，一条 429；删除会话不恢复额度，其他账号额度独立               |

既有 `test/ai-conversations.db-spec.ts` 的 4 项仓储数据库测试继续覆盖租约过期、旧 generation token fencing、近期四问及更细粒度并发。两组共 26 项真实数据库测试；原替身 HTTP 测试另行保留，不混称真实数据库证据。

## 运行方式

先准备已迁移、已 seed 的专用数据库，设置 `DATABASE_URL`；不得用生产数据库运行测试。

```powershell
pnpm exec vitest run --config vitest.config.database.ts test/ai-conversations-http.db-spec.ts test/ai-conversations.db-spec.ts
pnpm check
pnpm test:e2e
pnpm test:db
pnpm openapi:generate
```

测试仅清理自己创建的账号、会话、RAG 文档与雪场，不重置 schema。完整数据库结构校验见 [数据库验收](database-validation.md)，会话契约及租约规则见 [AI 会话](ai-conversations.md)。

## 验收边界与待办

固定向量仅证明索引、权限过滤、参数化检索与返回链路可运行，不能证明语义召回质量。外部模型由测试端口替身提供，尚未验证真实 DeepSeek 模型标识、账号额度、供应商流协议、真实 Embedding 模型兼容性、召回/引用准确性和费用。生产模型名须依据供应商当前可用清单验证，配置默认值本身不构成可用性证据。

本阶段验证请求入口的当前授权与会话 owner，不新增 AI 写事务内权限复核或撤权与生成提交之间的统一串行化协议。Guard 通过后、生成过程中撤权或来源撤回对在途回答的影响尚未解决；本轮检索完成后并不锁定源业务数据。已保存历史引用也不会自动随来源撤回擦除，需另外确定历史保留和隐私策略。

真实 Kafka/provider、浏览器/设备、大规模负载、来源回填、AI 管理及 RAG 运维契约仍需后续验收。整个项目尚未完成。
