# 资产停用事务授权

日期：2026-11-01。对应API-ASSET-02、D-41。接口、DTO/VO、OpenAPI1.46.0、依赖和迁移保持；修复管理资产删除在Guard之后未重新读取有效授权的问题。

## 事务边界

PrismaAssetRepository.deleteIfUnreferencedAdmin在Serializable事务内先通过IdentityAccess的Principal解析器读取当前活动账号、角色、权限和asset资源范围，要求management:portal:enter与content:asset:delete，并把当前all/self/selected范围与Guard快照规范化比较。范围变宽、缩小、冲突、失效或变成不支持的merchant均403，要求新请求重新授权。配置的自定义角色可使用该能力，不按商家或管理员名称推断。

授权后领取Asset行的FOR UPDATE锁。Serializable授权快照可能早于锁等待期间提交的引用，因此持锁后另用主库连接读取最新已提交的五类引用：雪场封面、相册、文章封面、动态图片、用户头像。该读取只能否决删除；有引用返回422，不可见404，读取失败则关闭写入路径。各生产关联写入持有同一Asset行的FOR SHARE锁，因此该独占锁持有期间不会新增关联。事务内仍按同一范围和引用条件更新，状态deleted与成功OperationLog原子提交；对象存储删除只在数据库提交后执行。

最新引用读取需要额外的主库连接，不能指向只读副本或缓存。连接池须为持锁事务之外的读取保留容量；池耗尽或读取失败会回滚并保留资产，不自动绕过检查。存储删除失败沿用既有处理，不声称已完成对象垃圾回收。

P2034、raw40001/40P01及P2010包装的对应SQLSTATE转换409，不自动重放旧删除请求。其他异常保留；实际审计INSERT失败仍回滚状态，不删除存储对象。Serializable与引用行锁可能把并发关联/变更判定为409；操作员应重新读取，不能把旧预读当成当前可删证明。

授权保证以事务快照为界；不能承诺取消快照建立后发生撤权的所有在途事务。列表与详情继续使用既有请求期Guard及D-41过滤，未改造成新的读取授权事务。普通本人删除接口未新增管理员授权要求。
