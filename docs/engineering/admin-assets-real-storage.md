## 复现与清理

按[Windows 独立存储说明](native-storage-validation.md)准备已校验运行时，在本仓执行 `pnpm test:native-storage`。需要全新临时 PostgreSQL 数据目录和空的独立桶；入口自己生成随机凭证与回环端口，不接受共享数据库或现有服务地址。第三方运行时和日志留在 D 盘，不提交到产品仓库。

测试增加了合成角色和商家资料，因此验收入口除原有资产/账号/会话/日志/Outbox/对象核对外，还比较前后 Role、Permission、UserRole、RolePermission、RoleDataScope、MerchantProfile 的数量，确认回到 seed 基线；查询公开 schema，确认不存在 `storage_audit_` 故障注入函数。随后停止本次 PG/MinIO/ClamAV 并核对四个端口关闭。用例自身核对删除审计的精确内容，清理后审计总数为零不替代执行中的成功/失败断言。

本轮扫描仍仅加载仓库无害测试定义，不证明生产完整病毒库、恶意样本覆盖或签名更新。上述合法管理员删除验证了对象正常移除；既有 204 仅保证逻辑停用的失败补偿规则保持，不声称生产异步物理清理、TLS/S3 灾备、浏览器/设备预览已经完成。实际结果见下节。
