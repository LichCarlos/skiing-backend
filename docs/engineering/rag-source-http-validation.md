# RAG 来源管理持久化联调

负责人：Backend。契约：OpenAPI 1.51.1 / 143 操作，24 项迁移。沿用已确认的来源管理协议，生产 API、领域规则和数据库结构不变。运行步骤见[独立管理端 HTTP 验收](admin-authorization-http-validation.md)，结果见[本轮证据](../validation/rag-source-http-20261103.json)。

`scripts/admin-authorization-http-fixture.ts` 为隔离库准备三个 RAG 来源：已发布项目知识对应的公开已索引来源、已撤回项目知识对应的历史失败来源，以及不支持运维查询的收益来源。公开来源使用当前 projectSourceState 策略快照，并通过参数化 SQL 写入两个真实 vector(1024) 分块。内部正文、Metadata、分块及收益均带合成标记，供客户端检查响应不含私有内容。

独立 Web 二十一项通过后，验证器直接读取数据库核对：

- 主来源控制版本 1→7、索引代次 0→6，最终 pending、人工启用、IndexedAt 为空；停用删除全部分块。
- 四条 `rag.source.reindex-requested.v1` 事件对应控制版本 2/4/5/7，事件 ID 与客户端结果完全匹配，身份 Payload 精确匹配，状态 pending、Attempts=0。
- 六次控制变更按操作日志顺序逐条匹配原因、账号快照、前后版本和事件 ID；同状态启用无控制审计。并发两次启用只有一条成功审计和事件。
- 被拒绝请求没有成功审计；失败及不支持的来源版本、代次、状态保持；底层项目知识正文、发布状态和版本不变。
- 原合法雪场写入仍只有一条 `ski_resort` Outbox；总事件数为五，Inbox 无消费记录。原权限、字段、商家隔离、会话审计与退出断言保留。

入口执行全新临时集群初始化、24 项迁移、双 seed、前后 db:verify 和后置夹具核对，再停止本次 Node/PostgreSQL。必须同时确认报告 completed/stopped/serverStopped、端口无监听、postmaster.pid 和初始化密码文件不存在。仅客户端退出 0 不足以通过。

首轮 Web 17 通过 / 4 失败，是授权变更后旧测试继续使用陈旧身份快照；生产代码正确拒绝。失败环境已停止，日志保留，在全新隔离库修正测试后复验。前端新增六个 RAG 场景及边界说明记录在 Web 本仓工程文档；后端测试不依赖该仓源码启动。

本套件只验证实际 HTTP 与事务持久化，Kafka 投递和消费者关闭，不调用 Embedding 或对话模型，也不启动 Docker。不能将四条待投递事件记为索引完成或供应商验收。整体项目仍有商家资料生命周期、雪场操作原因、账号删除及浏览器/设备/生产部署等待完成项。
