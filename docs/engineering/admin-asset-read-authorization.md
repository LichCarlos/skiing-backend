# 管理端资产签名前后的读取授权

维护：Backend。日期：2026-11-04。范围：现有 `GET /admin/assets` 和 `GET /admin/assets/:assetId`。接口、DTO/VO、权限目录、依赖、schema 与迁移保持，OpenAPI 仍为 1.51.1 / 143 操作。

## 行为与工程边界

此前列表和详情依赖 Guard 建立的权限与数据范围，异步签名后直接返回。签名期间撤权或资产转移时，旧结果可能包含可下载 URL。现在 Controller 将服务端认证账号 ID 传入用例，用例在查询前和签名后调用仓储的 `verifyReadAccess`；账号 ID 不来自请求 DTO。

每次复核使用独立 RepeatableRead 事务，重建当前账号、有效角色、管理入口及显式 `content:asset:list` grant，重新解析 asset 数据范围。当前范围必须与 Guard 解析的范围一致；缩小、扩大、冲突、缺失或不支持的 merchant 范围均拒绝。read grant 与 delete grant 各自独立，不因具备删除权限而自动允许读取。

签名后的事务同时按当前范围读取返回页的全部资产，核对 AssetId、OwnerUserId、StorageKey、Status。目标消失、归属改变、状态改变或换键返回 404；权限或范围变化返回 403，整次响应不包含已生成链接。空列表也执行最后授权检查，避免空分页绕过复核。删除接口继续使用自己的事务授权，不附加 list 权限要求。

签名调用位于数据库事务之外，不持锁等待 S3；列表批量复核一次，避免每个资产单独重建主体。列表上限仍为 100。查询与签名不构成跨系统原子事务，最后快照之后的变化不能即时取消响应。并发新增其他资产也不保证使原分页 total 变成新的瞬时总数。

已签发 URL 仍保留原定 900 秒有效期。本轮真实测试会捕获签名器生成的 URL 并确认在接口拒绝后仍可下载，以明确 HTTP 响应拒绝与存储能力撤销的区别；对象实际删除后 URL 返回 404。

## 验证设计

定向单测覆盖 list/detail 前后检查顺序、签名前拒绝不查询/不签名、签名后拒绝、目标变更拒绝、空分页复核，以及读取权限独立和当前账号/角色/入口/成员/范围/目录状态。既有删除测试保持。

真实 MinIO/clamd/PostgreSQL 专项保留所有生产 Guard、Repository、Scanner、AWS SDK 及签名器。对列表和详情分别在实际签名完成后停用账号、停用角色、移除读 grant、移除管理入口、改变范围或转移资产；检查 403/404、HTTP 无签名、对象与字节保留。另在 Guard 后/查询前解绑、签名期间实际执行本人删除，以及空分页查询后停用角色。观察器调用实际方法后再提交数据库变化，不伪造签名或对象状态。

运行入口沿用 [Windows 独立存储验收](native-storage-validation.md) 的 `pnpm test:native-storage`；全业务数据库另用 `pnpm test:native-db`。最终执行结果、源码与三仓工程检查见[本轮证据](../validation/admin-asset-read-authorization-20261104.json)。
