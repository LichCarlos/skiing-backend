# 动态字段配置到商家写入与公开读取验收

日期：2026-11-04。维护：Backend。对应 API-M10、API-R01/02、API-M02/03。沿用 OpenAPI 1.51.1 / 143 操作、24 项迁移；本轮仅增加数据库 HTTP 测试及验收文档，业务实现、依赖与契约保持。

首轮全库运行保留原845项通过，但测试装配漏全局ConfigModule而使新增13项未执行；专项复验又发现管理员夹具仍带注册角色，触发既定互斥保护。修正为真实应用的全局配置与管理员唯一角色后，专项13项先通过，再导出全新源码副本运行本节最终检查。失败日志和临时服务关闭记录保留，未修改产品规则或放宽断言。

新增 [13 项真实 HTTP/PostgreSQL 测试](../../test/custom-field-workflow.db-spec.ts)，装配 IdentityAccess、PlatformAdministration 和 ResortManagement 实际模块。注册、字典类型/父子项、字段组/定义/激活、角色创建/完整授权快照、账号角色绑定、商家写入与游客读取均经过实际 Controller、DTO、JWT/Guard、Application 和 Prisma。初始化管理员的角色绑定及有效 MerchantProfile 由隔离数据库夹具建立，不实现待定 D-49 商家建档接口；没有替换业务端口，也没有进行对象存储请求。

已有单选字段生命周期证据保留。本轮覆盖九种类型的组合，而不是把旧单选结果扩大为全部类型验收：

| 类型          | 同一表单中的有效值  | 被服务端拒绝的值    |
| ------------- | ------------------- | ------------------- |
| text          | 双板                | 超过 maxLength      |
| textarea      | 雪况良好            | 超过 maxLength      |
| integer       | 0                   | 1.5                 |
| decimal       | 12.5                | 超过 max=100        |
| boolean       | false               | 字符串 false        |
| date          | 2026-11-04          | 不存在的 2026-02-30 |
| single_select | 活动字典项 one      | 不存在的选项        |
| multi_select  | 父子字典项 one、two | 重复选项            |
| url           | HTTPS URL           | javascript 协议     |

每个类型各建一条包含全部九类值的雪场，核对响应和 JSONB，再提交非法值，逐项比较整条雪场记录、操作日志数量与 Outbox 数量不变；之后显式 null 清除该可选字段，其他八类值保持。创建字段时核对草稿、默认私有及默认值，随后通过版本 1 激活为版本 2。

管理员通过现有 PUT 完整授权快照，给同一商家账号配置两个普通角色：一个只提供字段读取，另一个只提供写入。实时字段目录合并为 canRead/canWrite 均 true，不依赖名为 merchant 的代码角色。已激活但无字段授权的第十个字段被目录排除，已知无权字段与未知字段的写入都返回 422，数据库、成功审计与 Outbox 不变。

替换写角色字段策略后，既有 token 仍能读取但写入被拒绝；恢复写权限并撤掉读权限后，目录变为只写，写入确实持久化，响应 customFields 为空，不能由写权限推导读权限。finally 恢复授权。非 system_admin 即使具有字段创建/编辑 grant，尝试启用 IsPublic 仍为 403，未新增字段或改变雪场/审计/Outbox。

独立雪场经商家送审、管理员发布后，游客初始读不到私有字段。管理员显式公开 text 字段后，只出现该字段的 key/label/value；撤回公开标记立即从游客响应移除，JSONB 中九类原值继续保留。此处不需要等待 Kafka，不将公开 HTTP 投影等同于 RAG 回填、供应商调用或浏览器验收。
