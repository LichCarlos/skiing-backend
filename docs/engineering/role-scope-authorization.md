## 授权边界

`Role.DataScope` 是资源未配置专用范围时的授权回退值，属于授权配置。仅 `system_admin` 可以配置；普通角色编辑权限不包含该能力。

| 操作                             | 普通角色管理员                                                   | system_admin                                               |
| -------------------------------- | ---------------------------------------------------------------- | ---------------------------------------------------------- |
| POST /admin/roles                | 有 create 权限及 role all 范围时，仅可创建 self 默认范围的空角色 | 可选择 self/merchant/all，仍需 create 权限及 role all 范围 |
| PATCH /admin/roles/:id           | 有 update 权限及目标范围时可维护元数据/状态，必须省略 dataScope  | 可显式配置 dataScope，仍需 update 权限及目标范围           |
| PUT /admin/roles/:id/permissions | 拒绝                                                             | 原子替换权限、资源范围与字段策略，仍需原有 grant/scope     |

PATCH 显式发送相同范围也需要系统管理员身份，不能利用“值未变化”跳过授权。新建 self 空角色没有任何权限，后续授权仍只能由系统管理员完成。system_admin 角色不可修改；注册基础角色不可停用，保持原有规则。

## 请求与事务

Controller 保留权限及 role scope 校验，并拒绝非系统管理员的范围配置。Prisma repository 在 Serializable 保存事务内重新读取操作者，要求账号 active；配置默认范围或替换授权快照时，还必须存在关联的 active system_admin 角色。查询不信任客户端身份字段或请求入口的旧快照。

检查在业务写入和授权集合删除之前进行；失败不修改角色或写成功审计。允许的写入与 before/after OperationLog 同事务提交，P2034 保持原有 409 重载重试语义。这不是对所有业务接口的授权撤销竞态或资源过滤的完整保证。
