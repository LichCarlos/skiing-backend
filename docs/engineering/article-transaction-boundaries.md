# 文章事务授权与输入边界

日期：2026-11-01。沿用已确认 API-M06、D-39/D-40；本轮无新增接口、表、依赖或迁移，OpenAPI 保持 1.45.0。工程实现与专项验证完成，完整回归结果以本页及实现追踪矩阵的最新记录为准。

## 本轮修正

`customFields` 是可省略但不可整体为 null 的对象。HTTP DTO 仅跳过 undefined，对 null、数组和标量返回 400，且不进入业务仓储；直接调用 Application 时，相同非法容器由领域校验返回 422。修正原先 `IsOptional` 与 `?? {}` 将整体 null 当作省略的行为。单个可写字段的 null 仍按其类型及必填规则校验；省略容器或字段保留原值，包括不可读的历史值。

文章 self 的账号编号、selected 的文章编号和服务端 actor 均限制为 1–2147483647 的安全整数。非法范围/主体拒绝授权；all 范围也不能绕过 actor 校验。HTTP 路由目标 ID 原有正 int4 校验保持，新增读取、编辑、删除、发布和撤回的边界回归。actor 和 scope 从服务端授权上下文获取，不由请求体指定。

文章全部活动字段的管理员特权在同一个事务内核实有效账号与 RoleKey、SystemRoleCode 均为 system_admin 的活动角色关联。仅有相同角色键不满足受保护身份；此类异常主体在加载字段前拒绝。普通自定义角色继续分别合并 CanRead/CanWrite，不因 all 记录范围获得字段权限。现有 Principal 规则已拒绝 system_admin 混绑其他有效角色，本轮未增加商家技术角色。

## 原有机制与新增覆盖

既有仓储读取使用 RepeatableRead，写入使用 Serializable；事务内重新解析主体、管理入口、`content:article:manage`、article 范围、字段定义/分组、读写策略和有效字典选项。请求范围必须与事务范围一致，selected 目标查询始终求交；这些机制此前已存在。本轮修正上述边界，并将撤权验证扩到列表、详情、字段目录、创建、编辑、发布、撤回、软删除八个入口。

真实数据库用例分别在旧授权上下文之后提交账号停用、角色停用、动作撤销、入口撤销、范围变更和范围冲突，再调用各入口，验证拒绝后文章、作者文章总数、审计和 Outbox 均无变化。字典项/类型在表单目录加载后停用，重新提交旧选项被拒绝；省略该字段仍保留存量值。真实受保护管理员无需显式字段 grant 即可管理活动字段，普通角色字段并集仍独立生效。

业务、OperationLog 与 Outbox 原子提交。新增故障注入先用真实 OutboxStore 追加事件，再抛错，验证文章与事件回滚；它验证事务边界，不代表真实 Kafka 投递故障。既有审计插入失败回滚和图片/分类共享锁测试保留。编辑 published 文章仍保持发布态，首次 PublishTime 与状态命令规则不变。

授权依据为事务快照：新事务复核此前已提交的撤权，不承诺即时取消快照建立后所有在途请求。字段字典写入规则与通用 RAG 公开父链规则仍各按原契约执行，本轮未扩大公开知识范围。
